# OpenList 回滚说明

## 重要限制

OpenList 在升级过程中可能执行 **数据库 / 索引迁移**。迁移成功后，**不能**假设仅替换旧版二进制即可安全回退。除非你有升级前完整备份且官方文档明确支持逆向迁移，否则应把回滚视为 **恢复备份**，而非「安装旧 SPK」。

## 回滚策略

### A. 升级失败、迁移未成功

1. 若套件处于异常状态，停止服务。
2. 从升级前备份还原 `/var/packages/openlist/var/`。
3. 重新安装上一已知良好的 SPK 版本（需与备份数据匹配）。

### B. 升级成功但功能异常

1. 停止套件。
2. 还原 `/var/packages/openlist/var/` 备份（含 `config.json` 与 `data.db*`）。
3. 安装与备份时期一致的 SPK 版本。
4. 若仅需恢复配置端口，可只还原 `config.json` 后重启（二进制版本须仍兼容该数据库 schema）。

## 不建议

- 卸载套件并勾选删除数据。
- 在未备份情况下反复在同一数据目录上试装不同主版本。

## 验证状态

| 阶段 | 本仓库是否已在真机验证 |
| --- | --- |
| 静态脚本（配置保留模拟） | 已在本仓库 CI/本地脚本中执行 |
| SPK 构建 | 视 CI Docker 构建是否成功而定 |
| DSM 真机安装 / 回滚 | **未验证** — 需持有人工授权与试装 |
